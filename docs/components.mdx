Installing AgenShield puts a small, fixed set of components on the Mac. Nothing
here needs configuring by hand — the installer places it all — but security and
IT teams reviewing the software should know exactly what is present, and support
needs a shared vocabulary for it.

## The components

<CardGroup cols={2}>
  <Card title="AgenShield app" icon="app-window">
    The menubar app and dashboard. Shows protection status, lets you protect an agent, and surfaces the approvals macOS needs a person to grant.
  </Card>
  <Card title="Background service" icon="server-cog">
    Always on. Applies the policy your organization publishes, keeps the record of what agents did, and reports device health to your console.
  </Card>
  <Card title="Security extension" icon="shield-check">
    An Apple Endpoint Security extension. Decides whether a protected agent may run a program or open a file.
  </Card>
  <Card title="Network extension" icon="route">
    An Apple Network Extension. Decides which destinations a protected agent may reach, and — if your organization enables inspection — records what it sent.
  </Card>
  <Card title="Command-line tool" icon="square-terminal">
    The `agenshield` command: setup, status, diagnostics, upgrade, uninstall.
  </Card>
  <Card title="Managed configuration" icon="file-badge">
    Your organization's signed policy, delivered from the console. Administrator-only on the device.
  </Card>
</CardGroup>

## Responsibilities

| Component          | Responsible for                                                                | Not responsible for                            |
| ------------------ | ------------------------------------------------------------------------------ | ---------------------------------------------- |
| AgenShield app     | Showing status; protecting an agent; surfacing approvals macOS requires        | Making policy decisions                        |
| Background service | Fetching and applying policy; recording activity; reporting device health      | Deciding individual file or network operations |
| Security extension | Allowing or blocking what a **protected agent** executes and reads             | Anything you or your other applications do     |
| Network extension  | Allowing or blocking where a **protected agent** connects; optional inspection | Your own browsing or non-agent traffic         |
| Command-line tool  | Setup, status, diagnostics, lifecycle                                          | Running in the background                      |

<Note>
  Enforcement applies to **protected AI agents** and the processes they start —
  not to you as the person using the Mac. AgenShield deliberately cannot block
  the system processes macOS needs to function; that limit is compiled into the
  signed security extension and cannot be changed by policy, by an administrator,
  or by anyone with access to the device. See
  [How AgenShield works](./how-it-works.mdx).
</Note>

## Where things are installed

| Path                           | What it is                                               |
| ------------------------------ | -------------------------------------------------------- |
| `/Applications/AgenShield.app` | The app, the dashboard, and both extensions              |
| `/Library/AgenShield/`         | The background service and command-line tool             |
| `/opt/agenshield/`             | Managed configuration (administrator-only)               |
| `/etc/agenshield/`             | Additional protection configuration (administrator-only) |
| `~/.agenshield/`               | Per-user settings, credentials, local records            |
| `/var/log/agenshield/`         | Service logs                                             |

Both extensions ship **inside** the app bundle. That is why the app must stay in
`/Applications` — moving or renaming it stops protection.

<Warning>
  `~/.agenshield/` holds this device's enrollment credentials. It is created
  owner-only — do not loosen its permissions, copy it between machines, or commit
  it to a repository.
</Warning>

## The three approvals macOS requires

macOS will not let any security product enable itself silently. On a Mac that is
**not** MDM-managed, someone with administrator rights must grant these once.
`agenshield activate` walks through them and detects each as you grant it.

<Steps>
  <Step title="Allow the system extensions">
    **System Settings → General → Login Items & Extensions.** Approve both
    AgenShield extensions. Until this is done, nothing is enforced.
  </Step>
  <Step title="Grant Full Disk Access">
    **System Settings → Privacy & Security → Full Disk Access.** Enable the
    AgenShield security extension. Without it the extension cannot evaluate file
    access and protection stays off — even though it may look approved.
  </Step>
  <Step title="Allow network filtering">
    Approve the **"Filter Network Content"** prompt. Without it, network rules
    have no effect.
  </Step>
</Steps>

On MDM-managed Macs your administrator pre-approves all three and nobody is
prompted — see the
[MDM deployment guide](./deployment/mdm/overview.mdx).

## Confirming everything is healthy

```bash
agenshield status
```

A healthy Mac reports the service running, both extensions active, a recent
successful policy sync, and each agent you chose to protect reporting as
protected.

The menubar icon shows the same at a glance — see
[The AgenShield app](./using/the-app.mdx) for the dashboard behind it:

| Menubar icon | Meaning                                                        |
| ------------ | -------------------------------------------------------------- |
| Solid shield | Protected — service running, extensions active, policy current |
| Outlined     | Action needed — an approval is pending in System Settings      |
| Slashed      | Not protecting — the service or an extension is not running    |

If something is not right, start with
[Common issues](./troubleshoot/common-issues.mdx).

## Removing AgenShield

```bash
sudo agenshield uninstall
```

This removes every component above, including the extensions and the managed
configuration. See
[Install and uninstall](./getting-started/install-and-uninstall.md) for what is left
behind and how to verify removal.
