Your organization has put your AI coding agent under AgenShield. This page is
what you actually need to know. The short version: **almost nothing changes**.

## What changed

Everything your agent runs, reads, and connects to is now checked against your
organization's policy, and recorded. Practically:

| Before                                 | Now                                                        |
| -------------------------------------- | ---------------------------------------------------------- |
| The agent could read anything you can  | Policy decides what it may read and write                  |
| The agent could connect anywhere       | Policy decides which destinations it may reach             |
| Nobody could say what it had done      | Every action is recorded and visible to your security team |
| You started it with your usual command | **Unchanged** — start it the way you always have           |

You do not need a new command to launch the agent, and nothing about your
day-to-day workflow changes.

## Checking what is protected

The quickest answer is the menubar icon; the
[dashboard](../using/the-app.mdx) shows the detail. From the terminal:

```bash
agenshield status
```

```text
Daemon:       ✓ Running

Targets:
  claudecode:
    Protection:   ✓ Protected
    Status:       running
  cursor:
    Protection:   ○ Not protected

Status: ⚠ PARTIAL - Not every agent is protected
```

- **Protected** — governed by AgenShield.
- **Not protected** — untouched. AgenShield is neither watching nor restricting it.

The overall status line summarizes the machine:

| Status        | Meaning                                                                |
| ------------- | ---------------------------------------------------------------------- |
| `SECURE`      | Everything AgenShield knows about is protected                         |
| `PARTIAL`     | At least one detected agent is not protected                           |
| `UNPROTECTED` | Nothing is protected yet — start the service or protect an agent       |
| `DEGRADED`    | The service is parked after repeated failures; run `agenshield doctor` |
| `CRITICAL`    | Something needs attention now — see the detail above the line          |

## When something is blocked

A blocked action fails the way an ordinary permissions problem fails. There is no
AgenShield dialog in your terminal:

| What was blocked            | What you see                                    |
| --------------------------- | ----------------------------------------------- |
| Running a program           | The command fails to start, as if not permitted |
| Reading or writing a file   | A permission-denied error                       |
| Connecting to a destination | The connection fails or times out               |

**Do not work around it.** Every block is recorded with the rule that caused it,
and that record is exactly what your administrator needs to fix the policy. Send
them:

- what you were trying to do
- roughly when it happened
- the error your agent reported

If your organization is in **monitor** mode, nothing is being blocked at all — a
failure you are seeing has another cause. Check
[Common issues](../troubleshoot/common-issues.mdx).

## Skills and connectors

Skills, extensions, and MCP connectors your agent loads are treated as governed
resources: AgenShield records which ones appear and your organization decides
whether each is approved.

If you have improved a curated skill your organization publishes, you can propose
the change back rather than editing it locally:

```bash
agenshield skill drafts list                  # what you have edited locally
agenshield skill propose-update <skill-name>  # submit it for admin review
agenshield skill drafts discard <skill-name>  # throw your local edits away
```

Local edits to a curated skill are saved as drafts. Proposing sends yours for
review; if it is accepted, everyone gets it.

## Signing in

```bash
agenshield login
```

Signing in links this Mac to your user account so policy can apply rules scoped
to your team, role, or group. Until you do, only device-wide rules apply. It uses
a device-code flow — the terminal shows a code, you confirm it in the browser.

## Everyday commands

| Command              | What it does                                         |
| -------------------- | ---------------------------------------------------- |
| `agenshield status`  | Is protection active, and which agents are protected |
| `agenshield doctor`  | Diagnose a problem; `--fix` attempts a repair        |
| `agenshield logs`    | Stream local logs while reproducing something        |
| `agenshield upgrade` | Update to the latest release                         |

## Frequently asked

**Can I turn it off?**
No — policy is managed centrally by design, and there is no local override. Ask
whoever administers AgenShield for your organization.

**Is it watching what I do?**
No. Enforcement and recording are scoped to protected agents. Your own commands,
files, browsing, and other applications are not observed. See
[Privacy and data handling](../configuration/privacy-and-data.mdx).

**Will it slow my Mac down?**
Decisions are made in the kernel and cached. You should not notice it in normal
use. If you do, that is a bug — run `agenshield doctor` and report it.

**Can it lock me out of my Mac?**
No. The processes and system paths macOS needs can never be denied — those limits
are compiled into the signed security extension and are not configurable. If
AgenShield ever starts denying an unusual volume of ordinary activity, it stands
itself down automatically.
